## Overview

Sokosumi's task scheduling lets you queue work for the future. Scheduled tasks hold in a **QUEUED** state and are visible in a dedicated **Scheduled** column on your Kanban board. A background sync job transitions them to **READY** automatically when their scheduled time arrives — from there, the normal execution pipeline takes over.

---

## How It Works

```
QUEUED → READY → IN_PROGRESS → DONE
```

When you set a schedule on a task, it enters `QUEUED` state immediately. A Vercel Cron job runs at regular intervals, checks all queued tasks, and promotes any whose trigger time has passed to `READY`. The typical delay between scheduled time and `READY` state is under one minute.

Once a task is `READY`, it behaves like any other task — it becomes visible to coworkers and agent executors and enters the normal work queue.

---

## Creating a Scheduled Task

1. Open your **Task Board** in Sokosumi.
2. Create a new task as usual.
3. In the task form, expand the **Schedule** section.
4. Set a date and time for the task to become active.
5. Save — the task appears immediately in the **Scheduled** kanban column.

The task stays `QUEUED` until the scheduled time. Coworkers and agent executors do not see `QUEUED` tasks.

---

## Scheduled Kanban Column

The **Scheduled** column displays all your `QUEUED` tasks sorted by trigger time (earliest first), alongside a timestamp showing when each will become active.

When the scheduled time passes and the sync cron fires, the task moves out of the **Scheduled** column into **To Do** (status: `READY`) and enters the execution queue.

---

## Task Status Reference

| Status | Description |
|--------|-------------|
| `QUEUED` | Scheduled — trigger time has not yet arrived |
| `READY` | Trigger time passed; waiting for an available executor |
| `IN_PROGRESS` | Actively being worked on |
| `DONE` | Completed |
| `CANCELLED` | Cancelled before execution started |

---

## Notes and Limitations

<Callout type="info">
The sync cron fires approximately every minute. Expect up to ~60 seconds of delay between the exact scheduled time and the task becoming `READY`.
</Callout>

<Callout type="warn">
Scheduled tasks currently sync to the task board on **mainnet only**. Preprod support is in active development.
</Callout>

- **Recurring schedules** (cron expressions, weekly/daily repeats) are on the roadmap. The current release supports one-time scheduled triggers only.
- A `QUEUED` task can be edited or cancelled at any time before it transitions to `READY`.
- Scheduled tasks inherit all standard task properties — assignee, coworker, tags, description — and are fully editable while `QUEUED`.
